# OnFly client app — PWA + App Store shell

Clients use the same portal (`/portal` — book, quote, track, login). Two packaging layers:

## 1. PWA (shipped now)

- Manifest: `public/portal.webmanifest` (standalone, cream/gold theme).
- Apple meta + touch icon in `index.html`.
- Service worker: `public/sw.js` (Chromium installability).
- In-app **Add to Home Screen** control on the first portal page (`/portal` landing + signed-in Trips home). Also on Account. iOS shows Safari Share steps; Chrome can prompt Install when available.

**iPhone:** On `/portal`, tap **Add to Home Screen** → follow Share → Add to Home Screen → open the OnFly icon (full-screen).

**Android:** On `/portal`, tap **Add to Home Screen** (or Install when Chrome offers it).

Regenerate icons after brand mark changes:

```bash
node scripts/generate-pwa-icons.mjs
```

## 2. Capacitor App Store shell (scaffolded)

Wraps the built web app in a native WebView for TestFlight / Play Console.

```bash
npm run build
npm run cap:sync
npm run cap:open:ios      # requires macOS + Xcode + Apple Developer
npm run cap:open:android  # Android Studio
```

| Item | Value |
|------|--------|
| App ID | `com.onflyair.client` |
| App name | OnFly |
| Web dir | `dist` |
| Cold start | native shell redirects `/` → `/portal` |

**Still required on a Mac for iOS:** signing, icons/splash in Xcode assets, privacy strings, TestFlight upload, App Store review. Push notifications can come later via Capacitor push plugins — not required for the first shell.

Config: `capacitor.config.ts`. Native projects: `ios/`, `android/` (generated by Capacitor; sync after each web build).
